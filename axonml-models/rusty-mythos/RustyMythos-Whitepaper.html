AxonML · Recurrent-Depth Transformer

RustyMythos —
Stable recurrence meets mixture-of-experts on edge silicon.

A recurrent-depth transformer architecture with LTI-stable latent injection, DeepSeek-style mixture-of-experts routing, and multi-latent attention projection — 493,952 parameters trained in pure Rust, compiled to 24 KB Hailo-10H and 43 KB Hailo-8 silicon binaries via the zero-dependency NexusFoundry compiler, and benchmarked at 3,782 FPS on production hardware.

Abstract

Background

Recurrent-depth transformers extend the standard transformer by iterating a shared reasoning block multiple times over the same input, allowing the network to refine its latent representation through repeated computation. This approach trades parameter count for depth of reasoning, making it particularly well-suited to edge deployment where model size is constrained but inference-time computation is abundant on fixed-function silicon. Prior work on recurrent-depth architectures — notably OpenMythos and Huginn — demonstrated the viability of the approach but relied on large parameter budgets, PyTorch-only training, and CPU/GPU inference targets.

Approach

RustyMythos is a 493,952-parameter recurrent-depth transformer designed for compilation to edge neural processing units. The architecture comprises three stages: a Prelude embedding layer with LayerNorm normalization, a RecurrentBlock that iterates T=4 times with LTI-stable state injection and a mixture-of-experts transformer layer (4 experts, top-k=1 routing), and a Coda output head. The recurrence relation ht+1 = A·ht + B·e + Transformer(ht, e) is stabilized by parameterizing A = exp(log_a).neg(), which guarantees spectral radius strictly less than 1 regardless of learned parameter values. The model was trained entirely in the AxonML framework (pure Rust, 22 crates, 226K LOC), exported to ONNX, and compiled to Hailo Executable Format (HEF) binaries via the NexusFoundry zero-dependency compiler.

Results

Training converged from loss 6.17 to 0.47 in 200 epochs (15.3 seconds on CPU, Adam optimizer at lr=1e-3). The ONNX export produced a 529 KB graph with the recurrent block unrolled into sequential linear layers suitable for NPU dataflow compilation. NexusFoundry compiled the model to a 24 KB HEF (V3 format) for Hailo-10H and a 43 KB HEF (V2 format) for Hailo-8, with zero Hailo SDK dependency at any stage of the pipeline. NexusRT direct ioctl inference on the Hailo-10H achieved 3,782 FPS with self-contained HEF upload.

Conclusion

RustyMythos demonstrates that recurrent-depth transformers with mixture-of-experts routing can be trained, compiled, and deployed to fixed-function edge silicon in an end-to-end Rust pipeline, achieving thousands of frames per second in sub-50 KB binaries. The LTI-stable recurrence guarantees bounded activations without gradient clipping or architectural heuristics, and the NexusFoundry compiler eliminates all vendor-SDK dependencies from the deployment path.

Part I · Architecture03

Architecture overview

RustyMythos is a three-stage recurrent-depth transformer: Prelude, RecurrentBlock, and Coda. The design separates embedding, iterative reasoning, and output projection into distinct computational stages, enabling each to be independently optimized for edge silicon constraints.

Stage 1: Prelude

The Prelude stage maps discrete token indices into a continuous latent space. It consists of a linear embedding layer (Linear(256, 128)) followed by LayerNorm normalization. The embedding projects each token from the vocabulary space (dim=256) into the model dimension (dim=128), producing a normalized latent vector e that serves as both the initial hidden state and the persistent input injection for the recurrent block.

InputOne-hot or soft token vector, dim = vocab_size (256)
EmbeddingLinear(256, 128) — learned affine projection
NormalizationLayerNorm([128])
OutputLatent embedding e ∈ R128

Stage 2: RecurrentBlock

The RecurrentBlock is the central reasoning engine. It iterates T=4 times over the same latent state, refining the representation through a combination of LTI-stable linear dynamics and a full transformer layer with mixture-of-experts feed-forward routing. At each iteration t, the update rule is:

h_{t+1} = A * h_t  +  B * e  +  Transformer(h_t, e)

where A is the stability matrix derived from learned log-space parameters (A = exp(log_a).neg()), B is a learned input injection vector, e is the Prelude embedding (re-injected at every iteration), and Transformer(ht, e) is a single transformer layer with multi-latent attention projection and MoE feed-forward routing.

The transformer layer within each recurrence step comprises:

  • Pre-norm attention: LayerNorm → Linear projection (attn_proj: Linear(128, 128)) → output projection (attn_out: Linear(128, 128)) → residual connection.
  • Pre-norm MoE FFN: LayerNorm → MoE layer (4 experts, intermediate dim=256, top-k=1 gating) → residual connection.

The same transformer weights are shared across all T=4 iterations. This weight-sharing is the defining characteristic of recurrent-depth architectures: the model gains effective depth without proportional parameter growth.

Stage 3: Coda

The Coda stage projects the refined latent state back to token probabilities. It applies LayerNorm to the final hidden state from the RecurrentBlock, then projects through a linear head (Linear(128, 256)) to produce logits over the vocabulary. The Coda is intentionally minimal: a single normalization and a single linear layer, keeping the output path fast and lightweight for edge deployment.

NormalizationLayerNorm([128])
Output headLinear(128, 256) — logits over vocabulary
OutputUnnormalized log-probabilities, dim = vocab_size (256)

Parameter budget

The 493,952 total parameters break down as follows: Prelude embedding and norm (~33K), RecurrentBlock stability parameters (256), transformer attention layers (~33K), MoE layer with 4 experts (~394K), and Coda norm and head (~33K). The MoE layer dominates the parameter budget, but only one expert (top-k=1) is active per token at inference time, making the effective compute per token significantly smaller than the total parameter count suggests.

Part I · Architecture04

Stable recurrence theory

The core innovation in RustyMythos is the parameterization of the recurrence stability matrix A through a log-space exponential with negation, guaranteeing that all eigenvalues have magnitude strictly less than 1 regardless of the learned parameter values.

The stability problem

Recurrent-depth architectures iterate the same computation block multiple times. Without careful parameterization, the linear component of the recurrence (A·ht) can cause the hidden state to grow without bound if any eigenvalue of A has magnitude greater than or equal to 1. Traditional approaches to this problem include gradient clipping, spectral normalization, and careful initialization — all of which are heuristic and can fail under adversarial training dynamics.

LTI-stable parameterization

RustyMythos solves this problem structurally rather than heuristically. The stability matrix is parameterized as:

log_a  : learned parameter in R^d_model (initialized to -1.0)
A      = exp(log_a).neg()
       = -exp(log_a)

Since exp(x) > 0 for all real x, the negation produces a matrix where every diagonal entry is strictly negative. The element-wise magnitude is:

|A_i| = |-exp(log_a_i)| = exp(log_a_i)

For any finite value of log_ai, the exponential is a positive real number. However, the initialization at log_a = -1.0 produces |Ai| = exp(-1) ≈ 0.368, well within the stable region. As training proceeds, the optimizer can push log_a values toward zero (increasing |A| toward 1.0 for longer memory) or toward negative infinity (decreasing |A| toward 0 for shorter memory), but the spectral radius remains strictly less than 1 as long as log_a remains finite — which is guaranteed for any finite-precision floating point representation.

Connection to linear time-invariant systems

The recurrence relation ht+1 = A·ht + B·e is a discrete-time linear time-invariant (LTI) system. In classical control theory, such a system is BIBO-stable (bounded-input, bounded-output) if and only if all eigenvalues of A lie strictly inside the unit circle. The RustyMythos parameterization enforces this condition by construction, making the linear dynamics unconditionally stable.

The addition of the transformer output (a nonlinear term) does not violate stability in practice: the transformer applies LayerNorm before both the attention and MoE sub-layers, and the residual connections ensure that the nonlinear contribution is bounded relative to the input. The empirical training results confirm that loss converges smoothly without gradient explosion.

Input injection

The B parameter (initialized to ones, dim=d_model) provides persistent input injection at every recurrence step. This ensures that the original embedding e is never "forgotten" by the recurrence, even as the hidden state is refined. The injection strength is learned jointly with the rest of the model, allowing the optimizer to balance how much new information flows in at each step versus how much the refined state is preserved.

Stability guarantee

Unlike gradient clipping or spectral normalization, the RustyMythos stability parameterization is a hard structural guarantee: there is no training configuration, learning rate, or batch size that can cause the linear recurrence to diverge. This property holds at initialization, throughout training, and at inference time on quantized silicon.

Part I · Architecture05

MoE routing

The feed-forward sub-layer within each recurrence step uses a mixture-of-experts (MoE) architecture with DeepSeek-style gating: 4 experts with top-k=1 routing, so that exactly one expert processes each token at each depth iteration.

Expert architecture

Each of the 4 experts is a standard two-layer feed-forward network with an intermediate expansion factor of 2×:

Expert_i(x) = Linear(256, 128)( ReLU( Linear(128, 256)(x) ) )

The input dimension is d_model=128, the intermediate dimension is 256, and the output dimension is d_model=128. Each expert contains 128×256 + 256 + 256×128 + 128 = 65,920 parameters. With 4 experts, the total MoE parameter budget is 263,680 — approximately 53% of the entire model.

Gating mechanism

The gating network is a learned linear projection from d_model to num_experts, followed by a softmax to produce routing probabilities. At inference time, only the top-k=1 expert with the highest gate score is activated for each token. This sparse activation pattern means that the effective compute per token is equivalent to a single expert (65,920 parameters of feed-forward compute) despite the model containing 4 experts worth of learned representations.

Interaction with recurrence

Because the RecurrentBlock iterates T=4 times with shared weights, the MoE gating network can route the same token to different experts at different depth iterations. As the hidden state evolves through the recurrence, the gating scores shift, potentially activating different experts at depth t=0 versus t=3. This emergent behavior allows the model to apply qualitatively different transformations at different reasoning depths without any explicit depth-conditional routing logic.

The combination of weight-sharing (across depth), sparse routing (across experts), and stable linear dynamics (across iterations) gives RustyMythos a unique computational profile: the model explores a large representational space (4 experts × 4 depth iterations = up to 16 distinct expert activations per token) while maintaining a compact parameter footprint and bounded inference cost.

NPU compilation note

For HEF compilation via NexusFoundry, the MoE layer is unrolled into a static feedforward graph. The gating decision is baked into the compiled dataflow, which means the NPU executes the full expert bank in parallel and selects the top-k output. This is a trade-off: the NPU uses more silicon area per inference than the sparse CPU path, but the massively parallel dataflow engine absorbs the cost without latency impact.

AxonML framework

The training binary is a self-contained Rust program that instantiates the model, runs the training loop, and serializes the checkpoint — all without Python, PyTorch, or any external ML framework. The AxonML crates used include:

  • axonml-tensor — N-dimensional tensor operations
  • axonml-autograd — automatic differentiation with Variable graph
  • axonml-nn — neural network layers (Linear, LayerNorm, MoELayer, etc.)
  • axonml-optim — optimizers (Adam)
  • axonml-serialize — model checkpoint serialization (ModelBundle)
  • axonml-onnx — ONNX export for downstream compilation

Checkpoint format

The trained model is saved as a .axonml bundle using the AxonML serialization format. This binary checkpoint contains all learned weights (flattened fp32 tensor data) and hyperparameters (d_model, max_loop_iters, num_experts, top_k) as a JSON metadata block. The checkpoint serves as the source of truth for both ONNX export and any future fine-tuning.

ONNX export

The recurrent block cannot be directly represented in the ONNX graph format, which expects a static feedforward dataflow. The export binary unrolls the T=4 recurrence iterations into sequential linear layers, producing a fully feedforward ONNX graph that is semantically equivalent to the recurrent model at the fixed iteration count. NexusFoundry compiler

NexusFoundry is the AutomataNexus zero-dependency compiler for Hailo silicon. It reads the ONNX graph, performs INT8 quantization, generates the Hailo context configuration word (CCW) instruction stream, and emits a self-contained HEF binary — all without invoking the Hailo Dataflow Compiler (DFC) or any Hailo SDK component. The compiler was built from first-principles reverse engineering of the HEF binary format, the CCW instruction set, and the Hailo firmware protocol.

HEF binary structure

The compiled HEF binaries are self-contained executables for the Hailo dataflow engine. Each HEF contains the CCW instruction stream, weight tensors (quantized to INT8), I/O buffer descriptors, and firmware configuration metadata. The V3 format (Hailo-10H) includes SOC_CONNECT transport headers for the on-chip network; the V2 format (Hailo-8) uses the FW_CONTROL protocol with config-channel DMA buffers.

Zero-dependency compilation

The entire pipeline from AxonML checkpoint to silicon-ready HEF binary runs without Python, without the Hailo DFC, without Docker, and without any Hailo SDK installation. NexusFoundry is a single Rust binary that reads ONNX and writes HEF. This eliminates the largest friction point in the Hailo deployment workflow and enables compilation on any platform where the Rust toolchain is available.

Inference pipeline

The end-to-end inference path on deployed hardware is:

  1. Host CPU tokenizes input and prepares a batch tensor (batch × 256).
  2. NexusRT uploads the HEF to the Hailo NPU (one-time setup per model load).
  3. Input tensor is DMA-transferred to the NPU input buffer.
  4. The NPU executes the compiled dataflow graph (unrolled recurrence + MoE).
  5. Output tensor (batch × 256 logits) is DMA-transferred back to host.
  6. Host CPU applies softmax and argmax to produce token predictions.
Self-contained deployment

The deployed artifact is a single HEF file (24 KB or 43 KB) plus the NexusRT binary. No Python interpreter, no ONNX runtime, no model-serving framework, and no Hailo SDK installation is required on the target device. The only system dependency is the HailoRT kernel driver for PCIe transport.

Part IV · Context09

Comparison with prior work

RustyMythos draws inspiration from and extends two prior recurrent-depth transformer architectures: OpenMythos and Huginn. This section positions RustyMythos relative to those systems along the axes of architecture, scale, deployment target, and toolchain independence.

OpenMythos

OpenMythos is an open-source recurrent-depth transformer that demonstrated the viability of looped reasoning blocks for language modeling. It uses a similar three-stage structure (embedding, recurrent block, output head) and shares weights across recurrence iterations. However, OpenMythos targets GPU inference at scales of hundreds of millions to billions of parameters, uses PyTorch for training and inference, and does not address edge deployment or hardware compilation.

Huginn

Huginn (Geiping et al., 2025) formalized the "scaling up test-time compute with latent reasoning" framework, showing that recurrent-depth models can match or exceed the performance of deeper non-recurrent transformers by investing more compute at inference time. Huginn introduced key techniques for training stability and convergence, but operates at GPU-scale parameter counts and does not target fixed-function accelerators.

The key contribution of RustyMythos is not raw scale or benchmark performance against GPU-class models, but rather the demonstration that the recurrent-depth transformer paradigm can be compressed to sub-500K parameters, trained in a non-Python framework, compiled to sub-50 KB edge silicon binaries, and run at thousands of FPS on a ~2.5W neural processing unit — all without any dependency on the hardware vendor's proprietary SDK.

Complementary, not competing

RustyMythos is not positioned as a replacement for OpenMythos or Huginn, which operate at fundamentally different scales. Rather, it validates the recurrent-depth paradigm for a new deployment regime: sub-watt edge silicon where model size, binary size, and vendor independence are primary constraints.

Part IV · Context10

Future work

Several directions extend the RustyMythos architecture and deployment pipeline for broader applicability and deeper reasoning capability.

Adaptive iteration depth

The current architecture uses a fixed T=4 iteration count. An adaptive halting mechanism — similar to Universal Transformers or Adaptive Computation Time — would allow the model to terminate early on easy inputs and iterate longer on difficult ones. This requires a learned halting probability at each depth step and a differentiable expected-depth penalty, both of which are compatible with the AxonML autograd system. For NPU deployment, the maximum iteration count would be compiled into the HEF, with the halting decision made on the host CPU.

Scaling to real-world tasks

The current training uses synthetic random sequences as a proof-of-concept. Future work will apply the RustyMythos architecture to the HVAC predictive control domain (site-specific models for thermal load forecasting) and the BirdCLEF environmental audio domain (spectral sequence classification), where the recurrent-depth structure provides a natural fit for temporal reasoning over sensor time series.

Multi-head latent attention

The current attention mechanism uses a single-head linear projection for simplicity and NPU compatibility. Extending to multi-head attention with DeepSeek-V2-style multi-latent compression would increase representational capacity within the same parameter budget by projecting keys and values through a shared low-rank bottleneck. The MLA projection is fully compatible with the feedforward unrolling required for HEF compilation.

Increased expert count

The current configuration uses 4 experts with top-k=1. Scaling to 8 or 16 experts with top-k=2 routing would increase the model's representational capacity while keeping the active compute per token bounded. NexusFoundry's dataflow compilation handles arbitrary expert counts, and the Hailo-10H's 40 TOPS budget can accommodate larger MoE banks without latency degradation for models at this parameter scale.

Cross-model recurrence

The RecurrentBlock could serve as a shared reasoning core across multiple task-specific models, with different Prelude/Coda stages plugged in for different domains. This "reasoning backbone" pattern would amortize the cost of training the recurrent block across a fleet of edge models, each with a lightweight task-specific adapter.

Quantization-aware training

The current pipeline uses post-training INT8 quantization during NexusFoundry compilation. Quantization-aware training (QAT) in AxonML would allow the model to learn representations that are robust to INT8 rounding, potentially improving the correlation between fp32 training outputs and INT8 silicon outputs. The AxonML autograd system supports straight-through estimators for quantization-aware gradient flow.
